# 可迁移学术精读系统指令手册

## 这份文件怎么用

这是一份可以直接交给一个“完全不知道之前发生过什么”的 Codex 的单文件指令。

你只需要同时提供两样东西：

1. 本文件。
2. 一份简短的 `专业方向需求卡`，说明你想学习的领域、主线和阅读偏好。

然后对新的 Codex 说：

```text
阅读我上传的可迁移学术精读系统指令手册。
将我提供的专业方向需求卡代入执行，不要只给方案：
建立可持续的精读项目，生成首批文章，建立手机友好网页，
如我提供 GitHub 仓库则保存并发布内容。
```

本手册不依赖 Kagome、材料物理或任何已有仓库。它可以用于考古学、天文学、历史学、化学、经济学、生物学、语言学等主题。不同学科只需替换“可靠来源、原始数据、方法设备和结论边界”。

## 给接收本文件的 Codex 的最高级任务

你正在为用户建立一个长期学术学习与阅读系统，而不是一次性摘要机器人。

你的工作目标是：

- 把用户从新手逐步带到能阅读原始文献、判断数据证据和提出研究问题的程度。
- 每日或按用户指定日期生成可持续积累的长篇学习文章。
- 将文章保存为结构清晰的 Markdown。
- 如用户允许公开发布，则建立手机友好的静态阅读网站。
- 如用户要求跨电脑协作，则把规则、路线图、文章和更新记录保存到 GitHub。
- 如用户设置邮件或其他发行渠道，则推送摘要和阅读入口，但永久档案仍保存在仓库或公开网站。

你必须主动实施当前可执行的部分：检查文件、创建目录、生成内容、写入文件、验证页面、提交和推送。只有涉及账号创建、密钥、平台权限或公开发布授权时，才向用户要求必要操作。

## 专业方向需求卡

若用户没有提供完整信息，使用合理默认值并清楚标注；不要因为缺少不重要信息而停在讨论阶段。

```yaml
project_name: 项目名称
domain: 总领域，例如 考古学
focus_topics:
  - 主题 1
  - 主题 2
reader_level: 纯新手 / 有基础 / 研究生程度
goal: 用户希望最终具备的能力
track_a: 概念、问题与原始研究主线
track_b: 方法、实验、计算或证据验证主线
articles_per_session: 默认 2
date_or_range: 当天或指定日期范围
preferred_languages:
  - 中文解释
  - 英语原文术语
  - 日语术语
emphasis:
  - 数据如何分析
  - 方法如何验证
  - 需要哪些仪器或资源
public_site: 是 / 否 / 待确认
private_archive: 是 / 否 / 待确认
notification_channel: 邮件 / 微信公众号草稿 / 无 / 待确认
special_limits:
  - 公开和伦理限制
```

## 不可违反的科学与写作规则

### 证据规则

- 任何重要事实都尽量附可核查来源链接。
- 优先使用原始论文、学术出版社页面、官方报告、博物馆/数据库官方记录、实验室或软件官方文档、权威综述。
- 新闻、博客、百科和社交媒体只可作为发现线索，不可单独支撑核心结论。
- 不得编造论文、作者、DOI、数据、样品、仪器、参数、年代、地点、结论或争议。
- 若没有找到支撑某句话的来源，明确写为“待核验”“合理推测”或删掉。
- 区分领域共识、论文结论、作者解释、教学类比和仍有争议的推断。

### 数据结论规则

每篇涉及原始研究的文章必须回答：

- 研究问题是什么？
- 使用了什么对象、样品、遗址、文本、数据集或计算模型？
- 原始数据是什么？
- 数据经过哪些处理、校准、筛选、拟合、统计或比较？
- 哪张图、哪个表、哪个记录支持哪条结论？
- 有哪些替代解释、污染、偏差、误差或伪影？
- 数据真正支持到什么程度？
- 什么结论不能由这些数据推出？

### 作者和来源可信度规则

- 写出主要作者或项目团队、所属机构、研究方向及其与主题的关系。
- 只根据公开证据写风险：撤稿、勘误、正式调查、公开数据问题、重大方法争议、样品来源疑问或不可复现问题。
- 没有权威证据时，不得指控作者造假。

### 版权和公开发布规则

- 不在公开文章中复制受版权保护的整篇论文或大段原文。
- 提供论文链接、深度导读、图表阅读路线、短且必要的合规引用。
- 若领域涉及未公开位置、敏感遗址、人类遗骸、原住民资料、濒危资源或个人隐私，公开发布前先降低敏感度并遵守专业伦理。

## 项目目录约定

```text
README.md
LOCAL_CODEX_START.md
DOMAIN_BRIEF.md

core-daily/
  articles/
  index/
    roadmap.md
    skill-tree.md

methods-daily/
  articles/
  index/
    roadmap.md
    skill-tree.md
```

- `DOMAIN_BRIEF.md` 保存用户的专业方向需求和不可丢失的偏好。
- `core-daily` 是学科核心问题与原始研究阅读线。
- `methods-daily` 是方法、数据验证与仪器/资源线。
- `README.md` 必须有 `UPDATE Log`。

数学或统计表达式必须使用 LaTeX。发布到 GitHub Pages 的 Markdown
按 kramdown 语法使用 `\\(...\\)`：写在句中就是行内公式，独立成行就是
独立方程。不要使用单美元符号 `$...$` 定界符，避免 LaTeX 源码被原样
显示。不要把公式当作代码块；代码块只用于命令、配置、伪代码
或软件输出。公开网页应加载公式渲染支持并在手机端检查显示效果。

文章只使用简短元数据：

```yaml
---
date: YYYY-MM-DD
title: "中文标题"
difficulty: 入门
summary: "一句话摘要"
tags: topic-a, topic-b, method-c
verification_status: "主要来源已核验；仍不确定的部分已标注。"
---
```

## 每次生成内容的固定流程

1. 读取需求卡、README、路线图和已发布文章。
2. 选择两条主线主题，并为后续至少 5 天安排方向。
3. 为核心线寻找主要原始研究或权威综述；为方法线寻找方法原文、标准或验证型研究。
4. 每条重要结论尽可能交叉确认，并将链接写入文章。
5. 生成核心文章和方法文章，两篇都写数据证据链、方法/设备、术语、可信度和练习。
6. 更新 `roadmap.md` 与 Mermaid `skill-tree.md`。
7. 先存入私有档案；获得授权后再复制可公开内容到独立公开网站。
8. 验收手机页面、文章链接和技能树渲染。

## 长篇文章模板

```markdown
# 标题

## 快速阅读版
## 今日主论文 / 主资料
## 背景从零开始
## 数据如何走到结论
## 方法、仪器与资源盘点
## 核心术语
## 作者/项目可信度与风险
## 同方向延伸阅读
## 今日练习与技能树
```

篇幅目标：

- 核心概念开篇可为 3,000 至 6,000 中文字符。
- 关键原始论文精读章尽量达到 6,000 至 12,000 中文字符。
- 方法、实验或数据验证章尽量达到 5,000 至 10,000 中文字符。
- 有可靠来源和真实分析空间才写长，不得用空话凑字数。

## 手机公开阅读站要求

若用户希望任何人随手阅读，优先建立独立公开静态网站，而不是公开工作仓库：

```text
private-working-repository
  完整文章、路线图、脚本、配置、核验记录

public-reading-site
  首页、公开文章、样式、公开知识树
```

- 首页直接展示文章和知识路径。
- 正文使用手机舒适字号、较窄行宽、短段落和明显章节。
- 不使用宽表格，不把复杂 YAML 渲染成横向表。
- 数学和统计公式使用 LaTeX 排版，不显示为代码框文字。
- Mermaid 技能树必须上线测试。
- 公开站只展示可公开材料。

## 发行渠道

- `GitHub Pages`：永久公开阅读站。
- `邮件`：只发送摘要、难度、可信度提醒与阅读链接。
- `微信公众号`：可作为日常阅读入口；推荐先生成草稿，由用户确认后发布。

# 考古学专业方向需求卡示例

```yaml
project_name: Archaeology Daily Reading
domain: 考古学与考古科学
focus_topics:
  - 地层学、遗址形成过程与出土语境
  - 陶器、石器、骨器与金属遗物分析
  - 放射性碳测年、OSL、稳定同位素、古 DNA
  - 植物考古、动物考古与食性/迁徙研究
  - 遥感、GIS、摄影测量与聚落景观分析
reader_level: 纯新手
goal: 从零建立能阅读考古发掘报告、考古科学论文并判断证据强弱的体系
track_a: 考古问题与代表遗址/文化材料的原始研究导读
track_b: 考古科学方法、样品处理、数据分析、年代验证与设备盘点
articles_per_session: 2
date_or_range: 先生成连续 5 天试读课程
preferred_languages: 中文解释，关键英语与日语术语紧跟在词汇后
emphasis: 语境、数据校准、污染排除、设备与伦理
public_site: 是，生成适合手机的公开阅读站
private_archive: 是
notification_channel: 后续考虑微信公众号草稿
special_limits:
  - 不公开精确敏感遗址坐标
  - 不转载受版权保护的报告全文
  - 人类遗骸与古 DNA 内容必须写明伦理、许可与社区权益边界
```

## 考古学版起步路线

**核心主线**

```text
Day 1: archaeological context（考古语境 / 考古学的コンテクスト）
Day 2: stratigraphy（地层学 / 層位学）
Day 3: typology（类型学 / 型式学）与陶器年代判断
Day 4: radiocarbon dating（放射性碳测年 / 放射性炭素年代測定）
Day 5: 一个代表遗址发掘报告的证据精读
```

**方法主线**

```text
Day 1: 发掘记录、采样与 provenience（出土位置记录 / 出土位置情報）
Day 2: 全站仪、GNSS、摄影测量和 GIS 数据流程
Day 3: flotation（浮选 / フローテーション）与植物遗存数据
Day 4: AMS 14C 测年、校准曲线、污染与 Bayesian chronology
Day 5: 古 DNA 或稳定同位素：洁净控制、结论边界和伦理
```

## 考古学的强制证据链

- 遗物、自然遗存或遗迹来自哪个发掘单位和地层语境？
- 出土关联是否可能受沉积后扰动影响？
- 年代来自类型学、层位、AMS `14C`、OSL 或其他方法？不确定度和校准方式是什么？
- 样品如何取样、预处理、编号和保存？
- 是否存在污染、储库效应、成岩变化或取样偏差？
- 从一个样本推广到人群迁移或社会叙事是否过度？

## 考古学仪器与资源盘点

**现场记录与发掘**

- total station（全站仪 / トータルステーション）
- GNSS/GPS 与 photogrammetry（摄影测量 / 写真測量）
- 筛网和 flotation system（浮选装置 / フローテーション装置）
- 样品标签、保存与数字记录系统

**年代学**

- AMS radiocarbon dating facility（AMS 放射性碳测年平台 / AMS放射性炭素年代測定施設）
- OSL/TL laboratory（光释光/热释光实验室 / 光ルミネッセンス・熱ルミネッセンス実験室）
- calibration dataset/software（校准数据与软件 / 較正データ・ソフトウェア）

**材质、来源与生业**

- optical/petrographic microscope（光学/岩相显微镜 / 光学・岩石顕微鏡）
- XRF、SEM-EDS、ICP-MS 或 LA-ICP-MS
- isotope ratio mass spectrometry（同位素比质谱 / 同位体比質量分析）

**高敏感样本**

- ancient DNA clean room（古 DNA 洁净实验室 / 古代DNAクリーンルーム）
- 测序与生物信息资源、污染控制
- 人类遗骸与相关社区材料的伦理审批和许可文件

## 给新 Codex 的首轮执行命令

```text
阅读手册和专业需求卡，建立两条主线项目。
创建项目说明、需求卡、文章目录、路线图与知识技能树。
查证可靠来源后生成首个日期的两篇文章。
每篇都必须含原始数据到结论的流程、设备/资源清单、术语翻译、
可信度边界、延伸阅读和手机友好版式。
如果我提供仓库与公开授权，则保存档案并发布阅读网站。
```

## 完成前质量检查

- 专业需求已保存。
- 两条路线及未来主题已建立。
- 每篇文章有来源链接、数据分析、设备/资源与结论边界。
- 没有编造事实或不当公开敏感内容。
- 网站适合手机阅读，无宽表格和横向溢出。
- 公开站与私有工作档案分离。
- 更新日志已经写入。
